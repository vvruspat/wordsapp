# Архитектура Wordsapp

## Границы модулей

`app/` содержит маршруты и layouts Expo Router. `composition/` подключает
провайдеры, навигацию и hooks жизненного цикла приложения.

Бизнес-код разделён на независимые фичи: `account`, `catalog`, `dialogues`
и `training`. Экраны и компоненты отвечают за отображение и пользовательские
события; hooks и сервисы выполняют операции с данными. Фичи не импортируют
друг друга, включая типы. Например, диалог открывает тренировку через маршрут
с параметром `wordIds`.

Общие понятия находятся в `shared/`, инфраструктура WatermelonDB — в `db/`,
общие API-операции — в `api/`. Транспорт диалогов принадлежит своей фиче.
Общий UI в `components/` и `mob-ui/` не зависит от фич.

Направление зависимостей: композиция приложения → фичи → общий код.
`npm run architecture` проверяет эти границы, доступ компонентов к API/БД
и циклы, включая type-only imports, динамические imports и реэкспорты.

## Владельцы данных

| Данные | Владелец |
| --- | --- |
| Слова, переводы, каталоги, темы и синонимы | WatermelonDB; запись через сервисы `shared/vocabulary/` |
| Результаты упражнений | WatermelonDB; `progressService` сериализует запись по пользователю, слову и упражнению |
| Выбранные каталоги и темы | `shared/selection/selectionStore`, сохраняющий выбор в user settings |
| Доступные виды тренировок | Статический реестр `shared/progress/exercises.ts` и UI-метаданные `shared/training/presentation.ts` |
| IDs, переданные из знакомства со словами или диалога | `features/training/model/trainingSelection`; вход следующей сессии |
| Training pool, очередь IDs, текущий шаг и покрытие | Чистая модель `TrainingSession` |
| Words pool, данные задания, загрузка, ошибки и незавершённые записи | Vanilla Zustand controller `trainingController`; подготовка данных через `trainingService` и `wordsService` |
| Пользователь, токены, восстановление и обновление авторизации | `sessionOwner` и `sessionStore` |
| Диалог и его сообщения | Сервер, локальный кеш и runtime открытого диалога, ограниченный текущей пользовательской сессией |
| Синхронизация словаря и загрузка аудио | `vocabularyCoordinator` и `vocabularyAudio`; store хранит статус и переводы названий тем |

Каталоги и статистика читают локальную БД и подписываются на изменения нужных
колонок. Общий vocabulary store не дублирует таблицы слов и переводов.

## Тренировочная сессия

`useTrainingManager` соединяет React с controller. Смена пользователя, любого
из двух языков, каталогов, тем или входных IDs создаёт новый controller;
результаты операций предыдущей сессии не могут заменить текущие данные.
`ExerciseContext` передаёт события, управляет модальными окнами и обратной
связью. Подбор слов и запись прогресса принадлежат сервисам и модели сессии.

При подготовке фиксируется набор подходящих слов. Mixed использует до 20 слов;
при запуске из диалога его слова имеют приоритет, затем добавляются личные
слова и слова выбранных каталогов. Standalone не ограничен размером mixed.
Оба режима используют один механизм: в training pool находятся незавершённые
виды упражнений, у standalone — один вид. Mixed случайно выбирает следующий
вид из pool. Доступность listening зависит от готовности аудио.

Покрытие слова для упражнения означает **score > 0**. Незавершённые слова
выбираются раньше освоенных. При 100% упражнение исключается из training pool;
пустой training pool завершает сессию. Отсутствие подходящих слов отображается
отдельно от загрузки и ошибки. Пустая выборка до первой синхронизации
перечитывается после неё. Фоновая синхронизация не меняет уже сформированный
непустой words pool и знаменатель прогресса текущей сессии.

Каждый результат привязан к сессии и показанному шагу. Повторное событие
не создаёт вторую запись, устаревшее событие игнорируется. Matching сохраняет
результаты нескольких слов одного шага отдельно. Переход к следующему заданию
ожидает записи прогресса; ошибка записи требует retry и не считается успехом.

Продолжение завершённого standalone запускает review того же упражнения.
Покрытие этого прохода начинается заново в памяти, сохранённые scores остаются.
Смена упражнения завершает review и возвращает покрытие из сохранённого
прогресса. Правила проверки ответов находятся в чистой модели, а допустимые
переводы и синонимы подготавливает `wordsService`.

## Авторизация, синхронизация и offline

`sessionOwner` единолично восстанавливает и обновляет токены и наблюдает
пользователя в БД. Обновление токенов запускается за семь дней до expiry.
Logout отменяет публикацию устаревших операций, снимает подписку, очищает
временный выбор и состояние сессии, сериализует удаление SecureStore tokens.
Локальные таблицы словаря, прогресса и кеша сохраняются.

Смена любого языка инвалидирует старые операции словаря и аудио. Один
coordinator объединяет одновременные синхронизации одной пользовательской
сессии и пары языков. Первая загрузка показывает состояние синхронизации;
при наличии кеша словарь доступен во время фонового обновления.

Словарь обновляется через upsert по серверным ключам с сохранением локальных
путей загруженного аудио. Это обновление серверных данных, без отдельного
механизма разрешения конфликтов. Ошибки аудиозагрузки оставляют remote fallback;
повторная загрузка запускается существующими lifecycle/download triggers.
Постоянной очереди загрузок нет.

Прогресс тренировок сохраняется локально. `shared/progress/dormantLearningSync.ts`
содержит неиспользуемую реализацию отправки: она не подключена и не является
очередью для последующей синхронизации. Offline не считается успешной серверной
синхронизацией.

Диалоги кешируют историю и черновики в WatermelonDB; отправка сообщений
и добавление слов требуют сети. Ошибка кеша допускает повторное чтение сервера,
а отсутствие кеша без сети отображается как offline/error. Позднее восстановление
черновика не перезаписывает уже набранный текст.

## Добавление упражнения

1. Добавить стабильный ID в `shared/progress/exercises.ts` и UI-метаданные
   в `shared/training/presentation.ts`. Существующие persisted IDs не переименовывать.
2. Добавить компонент упражнения и renderer в `TrainingAppWrapper` внутри
   `features/training/`. Получать подготовленные данные из words pool,
   отправлять результат через события.
3. Новые данные готовить в сервисах, чистые правила — в модели. Подключить
   упражнение к существующему training pool.
4. Проверить standalone/mixed, завершение, ошибку записи и retry, повторные
   события и review. Выполнить [проверки проекта](../README.md#проверки)
   и сценарий в целевом runtime.
